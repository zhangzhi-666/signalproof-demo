# SignalProof 验收集设计

本目录保存固定验收输入和经 AI 辅助、独立数学核对后预先固定的预期结果。这里不声称已获外部人工审阅，也未进行盲测。`tests.json` 是课程要求的数学验收集；`robustness.json` 是单独的条件、定义域、能力边界与解析安全检查。测试执行器只能读取预期值进行比较，不应覆盖、反向生成或自动放宽这些预期。

## 数学验收集

| 领域 | 正确推导 | 错误推导 | 合计 |
| --- | ---: | ---: | ---: |
| 卷积 | 10 | 10 | 20 |
| 傅里叶变换 | 14 | 14 | 28 |
| 拉普拉斯变换 | 14 | 14 | 28 |
| Z 变换 | 12 | 12 | 24 |
| 合计 | 50 | 50 | 100 |

每对 `*-OK` / `*-ERR` 使用相同数学起点。正确答案以及错误位置在执行对应测试前写定；标签通过数学性质逐式核对，不从被测引擎的输出反向生成。负例是有目的的错误变异，覆盖符号、系数、变量替换、运算类型、初值与收敛域；不是统一在答案后面加常数。

`expectedFirstError` 是第一条可确认错误的相邻推导的目标行号，采用从 1 开始的编号。两行推导的错误在第 2 行。正确推导必须返回 `null`。

100 条链共包含 **110 个相邻步骤**。`step-oracles.json` 为每一步独立保存 `expectedLocalStatuses` 和数学理由，并绑定 `tests.json` 的 SHA-256。整链有错不意味着后续每一步都局部有错；例如 C10-ERR 的两步标签是 `wrong, correct`，F14-ERR 是 `correct, correct, wrong`，L14-ERR 与 Z12-ERR 是 `correct, wrong`。任何原始数据变更都需重新核对标签，不能通过重跑引擎来自动更新答案。

## 独立追加评测

`holdout.json` 保存另行构建的 32 条组合与边界案例，四领域各 8 条，共 41 个相邻步骤：15 条正确链、7 条错误链、8 条条件或能力不足链、2 条缺失 ROC 链。它包含复合尺度与时移、多路输入、初值代入、已声明频谱求导、非整数离散移位和定义域检查，分别保存整链、局部步骤及首错位置预期。

追加集不并入课程要求的 50 正确 / 50 错误基线。文件名中的 `holdout` 只是独立文件名，并不表示盲测：构建者了解规则库，标签由 AI 辅助独立数学核对，未获外部人工认证。预期为 `unknown` 的匹配只说明正确保留了不确定性，不能解读为完成了该数学证明。

## 规则覆盖映射

| 执行规则 | 固定测试前缀 | 主要判定对象 |
| --- | --- | --- |
| C01–C08 | C01–C08 | 交换、结合、分配、常数、冲激恒等、冲激移位、零元、卷积微分 |
| F01–F12 | F01–F12 | 线性、时移、频移、尺度、共轭、时微分、乘 t、卷积、乘积、冲激、指数、高斯 |
| L01–L10 | L01–L10 | 线性、一阶导数、二阶导数、乘 t、复频移、因果延迟、因果卷积、积分、阶跃、指数 |
| Z01–Z10 | Z01–Z10 | 线性、移位、反转、指数加权、乘 n、卷积、共轭、冲激、右边几何序列、左边几何序列 |

补充测试 C09–C10、F13–F14、L11–L14、Z11–Z12 验证离散冲激、复合变换、多步推导与真实边界，没有把重复例题称为新规则。X/H/G 的基础变换映射可以作为 F00/L00/Z00 单独注册，不能冒充上述性质规则。

## 需要在演示中保留的检查

- **C08：卷积微分。** 卷积的导数可以落在任意一侧，不应把两种相等写法相加。负例恰好多出一份。
- **C10：首错与传播。** 负例第 2 行把 `x(t-2)` 写为 `x(t+2)`，第 3 行相对于错误前提继续正确地移位。第一错误仍是第 2 行；第 3 行可以显示“局部成立，但继承上游错误”。
- **F04：负尺度。** `x(-2*t)` 的幅度系数是 `1/2`，不是 `-1/2`。
- **F09：归一化。** 在本项目 Fourier 约定下，时域乘积对应频域卷积必须有 `1/(2*pi)`。
- **F13：复合尺度与时移。** `x(2*(t-3))` 对应 `exp(-3*I*w)*X(w/2)/2`，不能把相位写成 `exp(-6*I*w)`。
- **F14：末行错误。** 前三行都正确；第 4 行将两个同项相加误写为相减。必须返回第 4 行，不能只比较首末式后返回第 2 行。
- **L02–L03、L11–L12：初值。** 非零、零初值及初始速度必须分别处理，不能统一假设为零。
- **L13、Z09：收敛域错误。** 表达式正确但 ROC 方向错误也必须判错。
- **L14：符号等价。** 带相同 ROC 的 `1/(s+2)` 与 `(s+2)/(s+2)^2` 应可由代数化简确认。
- **Z10：左边序列。** `-2^n*u(-n-1)` 的变换是 `z/(z-2)`，ROC 为 `abs(z)<2`。序列前面的负号不是变换结果前面再加负号。
- **Z12：中间结果之后出错。** 第 2 行变换正确，第 3 行将频域乘积改成和，首错必须为第 3 行。

## 数学约定及适用条件

1. Fourier 使用 `exp(-I*w*t)` 的正变换核，逆变换系数为 `1/(2*pi)`；t、w 实数。
2. Laplace 使用从 `0-` 开始的单边变换，一阶导数规则为 `s*X(s)-x(0-)`。初值通过 `context.initial` 显式提供。因果规则通过 `context.causal` 显式提供。
3. Z 使用双边求和，n 为整数，z 为复数。几何序列的表达式与 ROC 一起比较。
4. 泛型 x/h/g 的形式变换假定存在；未指定原始 ROC 时，泛型性质不声称给出精确 ROC。指数与阶跃等已知变换对检查显式 ROC。
5. 经典规则均按其适用条件执行。符号参数缺少正性、非零或初值条件时，不得以抽样结果补齐假设。
6. 代数化简需要保留定义域限制。若约去的分母因子尚未证明非零，或新表达式引入未确认的分母条件，应保留未知；不能宣称被约去的奇点因此有了函数值。变换对的 ROC 另行保留与检查。

## 边界集

`robustness.json` 共 24 条，独立于 50 正确 / 50 错误指标：

| 范围 | 测试 |
| --- | --- |
| 白名单解析、禁止导入/属性/文件操作 | R01–R05 |
| 除零、平方根的定义域 | R06–R07 |
| 正性、尺度非零与显式条件 | R08–R11 |
| 缺少 ROC 的不完整结论 | R12–R13 |
| 缺少因果和初值条件 | R14–R16 |
| 能力外表达式 | R17 |
| 可证明代数等价与函数定义替换 | R18–R19 |
| 收敛域边界与左右序列歧义 | R20–R21 |
| 采样点巧合不能证明恒等 | R22–R23 |
| 显式非零初值 | R24 |

R03–R05 的输入是测试数据，绝不能作为 Python 代码执行。解析器必须先进行 AST 白名单校验。解析拒绝使用 `InputError`，与数学上的 `unknown` 区分；旧边界集兼容结果中的 `inputRejected` 标志不可省略。评测器将解析拒绝、超时和异常分别记录为 `input_error`、`timeout`、`error`，不能当作数学证明成功或丢弃失败记录。

## 证据等级与统计要求

- `correct` 需要规则重写或符号恒等的证据；“若干采样点相同”只能作为辅助证据。
- `wrong` 需要规则结果不符、条件矛盾、ROC 冲突或合法定义域中的可靠反例。
- `unknown` 表示能力不足或证明前提不足，不能把它统计为正确推导；解析拒绝和运行失败另列。
- `incomplete` 用于表达式正确但必要 ROC 未提供。
- 引擎运行结果应报告总数、通过数、失败数、预期与实际状态、预期与实际首错行。不得只展示精度百分比而隐藏失败。
- 完成 100 条验收集只说明本固定数据集通过，不能据此宣称任意信号表达式都可正确处理。
- 本文是测试设计，不代表测试已经执行或通过；实际结果以测试运行报告为准。

## 指标定义与复现

在安装依赖后，于仓库根目录运行：

```sh
python -m unittest discover -s tests -v
python tools/benchmark.py --repeats 3 --output docs/benchmark-results.json
```

- **步骤判定准确率**：`localStatus` 与固定逐步标签完全一致的数量 / 预期步骤总数。基线分母为 110；缺失结果、异常和超时仍占分母。
- **整链判断准确率**：最终状态与预期状态一致的链数 / 总链数。基线分母为 100。
- **错链首错定位准确率**：同时返回 `wrong` 和正确首错目标行号的数量 / 预期错误链数。基线分母为 50，不能靠返回某个行号而状态仍为未知计为成功。
- **含无错误情况的端到端定位准确率**：整链状态与首错位置同时匹配，包括正确链应返回的 `null`。`unknown + null` 不能冒充已证明的正确链。
- **整例完全匹配率**：整链状态、首错位置及全部局部步骤状态同时符合预期。
- **判定覆盖率**：实际返回 `correct` 或 `wrong` 的链数 / 总链数。它与标签匹配率分开报告，避免将按预期返回未知误解为全部已解决。
- **时延**：在原生 Python 持久隔离进程中，对整条 `verify()` 调用用 `perf_counter` 计时，包含解析、规则推理、证据及结果生成。排除进程启动、导入、四领域预热、IPC、浏览器与 WASM 加载及网络时间。每案例默认超时 20 秒；超时的内核时延为 `null`，失败仍计入准确率分母，调用端超时等待另计入 `callerLatencyMs`。

默认三轮重复。报告的 `uniqueMetrics` 按每个案例第一次实测统计；`metrics` 公开所有重复的计数，`inconsistentCaseIds` 标明重复间结果是否变化。平均数、p50 和 p95 来自所有已完成的内核调用，分位数采用 `(N−1)×p` 的线性插值；不会把整链时延除以步数冒称独立测量的单步时延。超时数量与缺失时延数量同时公开。

JSON 和 CSV 报告包含每条预期与实际结果、领域分组、混淆计数、运行环境及源码和数据哈希。`source.unchangedDuringRun` 用于确认运行期间未混入另一版本代码。`docs/test-results.json` 为同份原生基线报告第一轮结果的兼容展示视图；`docs/examples-validation.json` 则记录当前引擎对 24 道教学案例的单独核验。二者不声称是浏览器性能测量。完整基准证据以 `docs/benchmark-results.json` 为准。
