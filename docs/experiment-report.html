01 · 目标与交付映射

实现一个有边界、可解释、可复现的信号推导检查系统。输入每一行表达式及条件，输出相邻步骤的局部结论、最早已确认错误、候选规则与修正建议。Web 与命令行共用同一个 Python 核心。

service 负责稳定 API、目录与样本调度；formatting 只负责 LaTeX，排版失败不会改变数学结论。浏览器 Worker 装载同一组模块并在独立线程运行，原生 CLI 在可终止的子进程中运行单次请求。

解析器使用 Python ast.parse 后逐节点白名单转换为 SymPy 树，不使用 eval 或 parse_expr。保留未化简的运算结构及分母列表；标准化在已知条件下执行代数化简、变换对代入和变量替换。原始输入、AST、标准式、LaTeX 与规则路径均可检查。

Expression := Number | Symbol | Function(Expression, ...)
            | +Expression | -Expression
            | Expression (+ | - | * | / | ^) Expression
Line       := Expression [; ROC: Condition]

每链2–16行，单表达式最多1200字符、250个AST节点、22层嵌套；数值幂和变量/函数列表另有限制。这些是输入边界，不是任意符号计算的复杂度保证；CLI与Web还提供墙钟超时隔离。

03 · 数学约定与判定流程

Fourier 采用角频率及核 e−jωt，逆变换系数为1/(2π)；Laplace 从0−开始、保留初值；Z为双边变换、n为整数。连续时移与时间缩放采用实参数，离散时移采用整数参数。对于已知基本变换对，表达式和ROC一起比较；泛型规则未给出精确ROC时不补造条件。

  1. 校验输入、上下文、原始分母与ROC。
  2. 尝试直接符号等价以及有界规则重写，记录每次重写及适用条件。
  3. 不能建立证明时，在合法定义域、给定ROC与声明变换对下寻找数值反例。找到可靠反例才判错；抽样相同不判正确。
  4. 从第一对相邻行向后扫描，保存第一个确认错误的目标行号。前面若存在未知或缺失条件，置 firstErrorCertain=false。
  5. 将候选正确式和提交式的表达式树比较，返回局部不匹配路径。仅替换出错行，之后重新验证全部步骤。

“最小错因”是相对于有界搜索找到的候选，给出最小局部结构差异；并非所有等价推导中的全局最小编辑，也不承诺诊断唯一。后续局部正确步骤可标记“继承前错”，不能因此修复整链。

状态含义
correct有规则证明或符号等价依据
wrong规则冲突、ROC冲突或合法反例
unknown前提不足、能力外或证据不足
incomplete代数结果成立但必要ROC缺失
inputRejected / error非法语法或请求；独立于数学未知记录

07 · 自评与迭代记录

依据课程验收点进行自评，不虚构教师分数。每轮使用“复现输入 → 固定期望 → 最小修复 → 回归检查”，不通过放宽标签掩盖缺陷。

第一轮 · 从演示走向完整工程

发现：已有网页能够交互，但核心集中在单一文件，缺少独立运行入口、可复现三项指标与完整提交说明。

修复：分离解析、规则、诊断、验证、格式化和API模块；增加超时隔离CLI、固定依赖与离线安装、Windows/Linux自动检查。为100条链另建110个局部步骤标签，追加32个组合与边界案例。

engine/、examples/、requirements.txt、tools/setup.py、.github/workflows/tests.yml；data/step-oracles.json、data/holdout.json。

第二轮 · 修复数学边界与无效反例

发现：独立挑战发现：ROC可能在省略后被错误重新引入，复指数边界未取实部，复杂时移或新分母约束可能绕过规则条件；数值见证可能违反正数、因果或已知变换对。

修复：追踪链内ROC，检查轴与边界；对规则成功分支同样检查定义域；限定见证满足声明条件；修正常数频率代入，并拒绝矛盾初值、非有限输入和过大整数。

tests/test_engine.py：ROC连续性、复指数、时移前提、分母、见证条件、谱函数代入、解析限制及首错确定性回归。

第三轮 · 审查指标口径与交付一致性

发现：报告可能混用旧测量与新代码；首错计数需同时检查错误状态，不能仅匹配空位置；格式化失败的退出码与报告ROC展示也需修正。

修复：报告生成前逐文件核对源码、数据、标签及基准脚本哈希；未知和超时保留在准确率分母，空时延不当作零；独立记录唯一案例与重复测量；补全ROC显示与CLI退出码。

tests/test_benchmark.py、tests/test_report.py；tools/benchmark.py、tools/generate_report.py；docs/benchmark-results.json/csv。

本轮完成标准：所有课程交付文件齐全；固定验收、独立逐步标签和边界回归可重跑；指标来自当次执行；源码哈希与报告一致；网页继续使用同一引擎。未来改进重点是更丰富的ROC集合表达、经过外部人工复核的数据集，以及更大范围的性质组合。

09 · 能力边界与结论

系统覆盖课程要求的四类运算和主要变换性质，能给出相邻步骤证据、首错及修正建议，并具有可复现的完整工程入口。优先给出可信结论，而非强行覆盖所有数学表达式。

  • 支持受限表达式语言；不识别自然语言证明、手写图片或任意LaTeX输入。
  • 形式规则以相关变换/卷积存在及题设条件一致为前提。不会自动证明所有存在性定理。
  • ROC支持实现中列明的半平面/圆内外与基本特殊情形；复杂环域或隐式集合超出范围时保留未知。
  • 有界搜索可能遗漏需要更多中间步骤的正确证明。抽样只用于寻找反例。
  • 图形展示性质示意，不冒充输入信号的真实仿真。固定回归结果及自评不等同于外部评分。
